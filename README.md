# Apple Pencil 兼容查询站

这是一个移动端优先的静态网站。用户先选择 iPad 的发布年份、系列、具体版本和使用目的，页面再给出兼容的 Apple Pencil、首选理由、功能限制和二手购买提示。

## 运行

项目不需要构建步骤，也不需要数据库或后端。用任意静态 HTTP 服务从本目录提供文件即可。

```powershell
python -m http.server 3012
```

打开 <http://127.0.0.1:3012/>。直接双击 `index.html` 也能看到静态内容，但查询参数恢复、外链和浏览器安全策略应通过 HTTP 服务检查。

如果要运行浏览器回归，先在本目录安装开发依赖：

```powershell
npm install
```

## 文件职责

- `index.html`：页面结构、四个导航页面和可访问性标记。
- `styles.css`：响应式布局、状态颜色、结果卡和动效。
- `app.js`：兼容矩阵、用途推荐、查询状态、URL 恢复和页面渲染。
- `site-data.js`：账号、价格和在售资料。这里的价格、库存和链接是人工维护资料，不是实时接口。
- `assets/`：本地头像和功能示意图。
- `verify_ui.cjs`：使用 Playwright 的浏览器回归脚本。

## 更新数据时的规则

1. 年份指 iPad 机型发布年份，不是用户购买年份。
2. 每个 `variants` 条目都必须在同一系列的 `devices` 中有对应键。
3. `devices[*].primary` 只能引用该设备的 `compatible` 中已有笔型。
4. Apple Pencil（USB-C）在界面中可以使用“USB-C 第三代笔”帮助用户理解，但正式名称必须保留。
5. 磁吸收纳、磁吸配对和磁吸充电分别填写，不能用一个“支持磁吸”替代。
6. 在售条目应提供 `pencil`、`url`、价格或价格说明和 `updatedAt`；页面会显示资料更新时间。没有独立商品页时，`url` 可以指向账号主页，但 `actionLabel` 必须明确写成“去小红书主页找商品”一类的文案，不能伪装成直接购买链接。将 `status` 设为 `inactive` 后，条目不会出现在在售页或结果购买入口。
7. 不要把未核对的价格、库存、成色或购买链接写成实时事实。

## 验证

从项目目录启动静态服务后，运行：

```powershell
node verify_ui.cjs
```

也可以使用 `npm run verify`。

脚本会检查多个视口、36 条当前兼容路径、URL 恢复、无兼容年份、二手避坑、FAQ、在售资料和横向溢出。实机配对、压感、Safari、微信内置浏览器和真实商品交易仍需要在目标环境单独确认。

## 当前边界

本项目没有登录、支付、订单、在线库存、管理后台或服务端 API。若以后接入这些能力，应先把兼容矩阵和在售资料从 `app.js` / `site-data.js` 中拆成有版本、有来源和有更新时间的数据层，再引入服务端接口。
